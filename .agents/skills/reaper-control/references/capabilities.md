# Возможности REAPER и MCP

Проверено 01.11.2026: установлен **7.82/macOS-arm64**. Последний стабильный
на [сайте REAPER](https://www.reaper.fm/download.php) — **7.84 от 28.10.2026**.
Обновление приложения в эту настройку не входит.

[ReaScript API](https://www.reaper.fm/sdk/reascript/reascripthelp.html)
документирует MIDI-пакеты, automation items, FX-контейнеры, маршрутизацию,
спектральные правки и параметры рендера. Онлайн-справка может опережать
установленную версию: для новых API проверять `APIExists`, для параметров —
успех getter и фактическое значение. Наличие функции не подтверждает поддержку
каждого её параметра. Для точной версии можно сгенерировать справку из REAPER.

## Что раскрывать агенту

Это план развития интерфейса MCP, а не заявление о готовности всех функций.

| Область | Что полезно пользователю | Следующий инструмент / проверка |
|---|---|---|
| Проект | видеть вкладку, дорожки, FX и несохранённые изменения | уже добавлены health и snapshot; расширить снимок master FX и items с пагинацией |
| MIDI | партии, CC, артикуляции, человеческие отклонения, ремап AD2 | чтение/пакетная правка по take GUID, проверка note count и времени; 7/8 и переменный темп |
| Аранжировка | секции, регионы, копирование, razor edits, fixed lanes/comping | операции над диапазоном с dry-run и expected project ID |
| FX | контейнеры, параллельные цепочки, параметры в Гц/дБ | дерево по FX GUID; поиск параметров, formatted values, чтение назад после записи |
| Сведение | шины, сайдчейн, автоматизация, обработка стемов | проверка sends и pin mapping; существующие mix_probe/mix_apply/mix_calibrate |
| Автоматизация | точки, огибающие, повторяемые automation items | пакетная правка выбранного диапазона с сохранением соседних точек |
| Рендер | мастер/стемы/регионы, сравнение обработок | запуск с восстановлением настроек, статус/отмена, проверка результата и LUFS |
| Аудио | stretch markers, take FX, spectral edits, выравнивание | сначала чтение и копия take; проверка источника и длины до/после |
| Расширения | SWS, ReaPack, JS_ReaScriptAPI | опрашивать доступность API; не устанавливать ради простой диагностики |

## Почему не включён профиль full

Текущий upstream — множество обёрток с неодинаковой полнотой и проверками.
В живом вызове `GetProjectName` вернул `{}`, а размер — `4/120.0`.
Один универсальный вызов API не умеет автоматически сериализовать указатели
и multiple-return значения Lua. Нужны типизированные операции, GUID объектов,
ограничение объёма ответа и проверки состояния, а не только больше имён tools.

## Очередь форка

1. Транспорт и диагностика — уникальные запросы, атомарная запись, отсутствие
   лимита 1000, ошибка вместо выдуманного темпа, снимок проекта.
2. Тесты на временной вкладке: MIDI/FX/routing/automation, проверка отмены
   и переключения проекта. Существующие integration tests upstream могут
   менять активный проект — на пользовательской вкладке их не запускать.
3. GUID-адресация, expected state и пакетные изменения с undo; затем
   инструмент рендера с восстановлением настроек и измерением результата.
4. Контейнеры FX, lanes/comping и spectral edits — отдельные адаптеры после
   проверки API на установленной версии.

В 7.83/7.84 интересны улучшения рендера, MIDI learn для sends и дорожек,
а также `GainReduction_dB` для поддерживающих его CLAP. 7.84 убрал добавленные
в 7.83 chmaha JSFX из установщика: не строить skill на предположении, что они
есть. [Изменения 7.84 и 7.83](https://www.reaper.fm/download.php).
