# Управление REAPER

## Сначала состояние

1. Обнаружить инструменты `reaper_health` и `reaper_project_snapshot`, прочитать
   их схемы и вызвать. Проверить версию, путь и session ID активного проекта, dirty,
   транспорт и дорожки. Если инструментов нет — обнаружить доступные MCP
   инструменты чтения; не считать отсутствие инструмента отсутствием API REAPER.
2. Если мост не отвечает, не повторять изменения: проверить процесс MCP,
   `cwd`, Python, каталог обмена и запущенный Lua-мост. Настройка —
   [references/setup.md](references/setup.md).
3. Перед правкой найти объект заново по GUID. Индексы дорожек и FX в низком
   уровне начинаются с 0; подпись «Track 1» в DSL — первый трек. После удаления,
   вставки или переключения вкладки прежние индексы недействительны.

## Выбор инструмента

| Задача | Как работать |
|---|---|
| MIDI и аранжировка | MCP для точечных правок; большой объём нот — пакет MIDI/ReaScript, один undo-блок. Время в секундах, долях и PPQ переводить API текущей карты темпа |
| FX | сначала список и GUID, точное имя плагина и параметры; значения с единицами проверять через formatted value, не угадывать нормализованный коэффициент |
| Маршрутизация | проверить каналы, sends и folder depth; сайдчейн 3/4 не гарантирует правильную карту входов VST |
| Автоматизация | читать режим, существующие points и automation items; изменять нужный диапазон, сохранять остальное |
| Рендер | копия/временные настройки с восстановлением; измерить файл, длительность, тишину, пики/LUFS по задаче |
| Новая песня / сведение | `reaper-song` / `reaper-mix`, перед выбором плагинов — `reaper-plugins` |
| API отсутствует в MCP | узкий ReaScript с проверкой проекта; сигнатуру сверить с локально сгенерированной справкой или официальной API-страницей |

Возможности и очередь развития — [references/capabilities.md](references/capabilities.md).
Не включать весь профиль MCP только ради одного инструмента: наличие регистрации
не доказывает корректность обёртки. В upstream есть неверно разобранные multiple-return API.

## Изменение и проверка

- Работать в пределах поручения. Пересборка, сведение и массовые правки — в
  новой копии проекта; несохранённые ручные изменения не затирать.
- До Lua-правки сравнить session ID проекта и ожидаемые объекты. Если они изменились,
  остановиться и перечитать состояние, а не искать «похожую» дорожку.
- Группировать правку в undo-блок; `PreventUIRefresh` и временные настройки
  восстанавливать даже при ошибке (`xpcall`). Ошибка MCP не означает, что
  изменений не было: сначала перечитать результат, затем решать о повторе.
- После правки повторить снимок и проверить именно обещанное: ноты/позиции,
  FX/параметры, sends, файл рендера. `ok` инструмента — не доказательство звука.
- Не сохранять, не запускать запись, воспроизведение или рендер ради простой
  диагностики. При калибровке со звуком заранее предупредить пользователя.

## Особенности установки

`claude/sidechain_dyneq` — имя реально установленного JSFX. Оно не связано
с агентом и должно сохраняться для совместимости старых проектов.
Перенос инструкций в Codex не переименовывает FX и медиа.
